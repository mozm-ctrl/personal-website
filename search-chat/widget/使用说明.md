## 这是什么

一个可以加进任何网站的「AI 聊天 + 联网搜索」组件：网页右下角出现一个聊天按钮，访客提问后，服务端调用大模型，需要时先上网搜索，回答里用 [1][2] 标注来源。

可选功能：接入网站自己的账号系统，**只有登录用户能用，每次提问从用户自己的积分里扣费**。

本文分三部分：

1. 在自己电脑上试用（给网站主人看效果）
2. 接入网站（给对方网站的技术人员）
3. 常见问题

更详细的接口和参数说明见同目录的 `README.md`。

## 一、在自己电脑上试用

需要：Mac / Linux 电脑，已安装 Go（1.26 以上）和 Ollama，并下载了模型 `qwen3:8b`（`ollama pull qwen3:8b`）。

**第 1 步：打开终端，整段复制粘贴下面的命令，按回车**

```bash
kill $(lsof -t -iTCP:3001 -sTCP:LISTEN) 2>/dev/null
cd ~/Documents/Codex/search-chat/widget
export LLM_BASE_URL=http://localhost:11434/v1
export LLM_MODEL=qwen3:8b
export LLM_REASONING_EFFORT=none
export PRICE_PER_REQUEST=0
export PRICE_PER_SEARCH_DUCKDUCKGO=0
export PRICE_PER_SEARCH_TAVILY=1
export PRICE_PER_SEARCH_BOCHA=1
go run ./examples/billing-demo
```

- 第一行会停掉之前还开着的示例，没有就什么都不做。
- 看到 `打开 http://localhost:3001……` 就是启动好了。**这个终端窗口不要关。**
- 每次新开终端都要重新粘贴整段（`export` 只对当前窗口有效）。

**第 2 步：浏览器打开 http://localhost:3001**

页面上有两个演示账号（密码都是 123456）：alice 有 10 积分，bob 有 1 积分。

| 操作 | 会看到 |
| --- | --- |
| 不登录，点右下角按钮提问 | 「请先登录」 |
| 点「以 alice 登录」，问「1+1」 | 正常回答，下方显示「本次未扣积分」 |
| alice 问「今天的科技新闻」 | 联网搜索后回答，带来源链接；用的是免费的 DuckDuckGo，不扣积分 |
| 点「以 bob 登录」后提问 | 「余额不足 去充值」（提问前要先冻结 2 积分，bob 只有 1） |
| 点「充值 10 积分」后再问 | 可以正常提问 |

**第 3 步：用完回到终端按 `Ctrl + C` 停止。**

说明：

- 这个页面只是演示，账号和余额都存在内存里，重启后恢复初始值。
- 只有你自己这台电脑能打开 localhost 地址，别人打不开。
- 本机没配置 Tavily / 博查的 Key，所以只会用 DuckDuckGo 搜索。

## 二、接入网站（给对方技术人员）

### 网站访客要做什么？

什么都不用做。访客只是打开网页，点聊天按钮提问。下面的配置只需要网站技术人员在服务器上做**一次**。

### 先选接入方式

| 对方网站 | 方式 | 能否按用户扣积分 |
| --- | --- | --- |
| 任何语言（PHP、Java、Node、Python……）或纯静态网站 | **A. 独立服务** | 不能，费用都记在网站主人的模型 Key 上 |
| 后端是 Go | **B. Go 包** | 能（可选） |

### 两种方式都要准备

1. **代码**：`search-chat/widget/` 整个文件夹。
2. **模型 Key**：去 DeepSeek、OpenAI、通义等平台注册、充值，拿到 API Key。正式网站一般不需要 Ollama。
3. **服务器**：一台能上外网的服务器，最好配好 HTTPS 域名。
4. **（可选）搜索 Key**：Tavily（https://tavily.com）或博查（https://open.bochaai.com）。DuckDuckGo 被限流或出错时用它们顶上；不配也能用，只是 DuckDuckGo 失败时这次就没法联网。

### 方式 A：独立服务（3 步）

**第 1 步：写配置文件。** 在 `widget` 文件夹里把 `.env.example` 复制为 `.env`，至少填：

```bash
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=你的模型Key
LLM_MODEL=deepseek-chat
ALLOWED_ORIGINS=https://www.你的网站.com
```

**第 2 步：在服务器上启动**（只做一次，服务器重启后会自动恢复）：

```bash
cd widget
docker build -t search-chat .
docker run -d --name search-chat -p 8080:8080 --env-file .env --restart unless-stopped search-chat
```

检查：浏览器打开 `http://服务器地址:8080/healthz`，看到 `{"ok":true,...}` 就正常。

**第 3 步：在网站每个页面的 `</body>` 前加一行：**

```html
<script src="https://聊天服务地址/chat-widget.js" data-endpoint="https://聊天服务地址/api/chat"></script>
```

刷新页面，右下角出现聊天按钮就完成了。

### 方式 B：Go 网站 + 按用户扣积分（4 步）

**第 1 步：** 把 `searchchat/` 文件夹复制进 Go 项目，执行 `go get github.com/PuerkitoBio/goquery golang.org/x/net`。

**第 2 步：写 4 个函数，接上自己的账号和余额表。**

| 函数 | 作用 |
| --- | --- |
| `Authenticate` | 校验用户的登录 Token，返回用户 ID；返回错误时提示「请先登录」 |
| `Reserve` | 提问前检查余额并冻结积分；余额不足时提示「余额不足」，不调用模型 |
| `Settle` | 回答成功后按实际用量结算，多冻结的退回 |
| `Refund` | 模型出错、超时或用户中途离开时，全额退回 |

`README.md` 的「接 SQL 数据库的参考写法」可以基本照抄，改成自己的表名和字段名。`examples/billing-demo/main.go` 是一个完整的可运行示例。

**第 3 步：在路由里挂上聊天服务，设置计费规则：**

```go
cfg := searchchat.ConfigFromEnv()           // 模型 Key 等仍从环境变量读取
cfg.Authenticate = myAuthenticate           // 第 2 步写的
cfg.Billing = &MyBilling{DB: db}            // 第 2 步写的
cfg.Pricing = searchchat.Pricing{
    PerRequest:   0,                                                         // 每次提问不收费
    SearchPrices: map[string]int64{"duckduckgo": 0, "tavily": 1, "bocha": 1}, // 只有用了收费搜索才扣 1 积分
}
cfg.DailyLimitPerUser = 50 // 可选：每人每天最多问 50 次
mux.Handle("/ai/", http.StripPrefix("/ai", searchchat.Handler(cfg)))
```

**第 4 步：在页面里加聊天组件，把用户的登录 Token 交给它**（二选一）：

```html
<!-- 登录 Token 存在 localStorage 里时，写上键名 -->
<script src="/ai/chat-widget.js"
        data-auth-storage="token"
        data-login-url="/login"
        data-recharge-url="/recharge"></script>
```

```js
// 或者在网站登录成功后调用；退出登录时 setToken(null)
window.SearchChat.setToken(token);
```

登录状态存在 Cookie 里的网站，不用设置这两项，在 `Authenticate` 里直接读 Cookie 即可。

> **重要：** 只在登录后的页面才显示聊天按钮是挡不住别人的，必须在服务端用 `Authenticate` 校验 Token。

### 计费规则怎么配

| 想要的效果 | 配置（环境变量） |
| --- | --- |
| 每次提问扣 1 积分（默认） | 什么都不填 |
| 每次提问扣 2 积分，每次搜索再加 1 | `PRICE_PER_REQUEST=2` `PRICE_PER_SEARCH=1` |
| 免费的 DuckDuckGo 不扣，用了收费搜索才扣 1 | `PRICE_PER_REQUEST=0` `PRICE_PER_SEARCH_DUCKDUCKGO=0` `PRICE_PER_SEARCH_TAVILY=1` `PRICE_PER_SEARCH_BOCHA=1` |
| 按 token 用量扣 | `BILLING_MODE=per_token` `PRICE_INPUT_PER_1K=2` `PRICE_OUTPUT_PER_1K=8` `MAX_CHARGE=20` |

规则说明：

- 提问前先按最高可能的费用**冻结**积分，回答后按实际用量多退少补，所以同一个用户同时发很多问题也不会扣成负数。余额不够冻结时不能提问。
- 模型出错、超时、用户中途关掉页面：全额退回。失败的搜索不收费。
- 只有方式 B 才能按用户扣费。

### 上线前检查

- [ ] `/healthz` 返回 `{"ok":true,...}`
- [ ] 网站是 https 时，聊天服务也是 https（最省事是用 Nginx 挂到网站同一个域名下）
- [ ] `ALLOWED_ORIGINS` 写的是网站的完整地址（含 `https://` 和 `www`）
- [ ] 模型 Key 只在服务器的环境变量 / `.env` 里，没有写进网页或提交到代码仓库
- [ ] （方式 B）未登录提问提示「请先登录」；登录后提问，回答下方显示扣了几积分

## 三、常见问题

**用户需要装 Ollama 或者开终端吗？**
不需要。Ollama 和终端命令只是在自己电脑上免费测试用的。正式网站用在线模型的 Key 即可。

**用的是哪个搜索引擎？**
先用免费的 DuckDuckGo；它被限流、出错或没结果时，才改用配置了 Key 的 Tavily / 博查（中文问题先博查，英文问题先 Tavily）。模型只有一个（`LLM_MODEL`），不会自动换。

**网站主人要付哪些钱？**
在线模型每次提问都会产生费用；DuckDuckGo 免费，Tavily / 博查按次收费。这些都记在网站主人自己的 Key 上，按用户扣积分只是把成本转给用户。如果设置成「每次提问不收费」，模型费由网站主人承担。

**聊天框显示「连不上聊天服务」？**
网站域名不在 `ALLOWED_ORIGINS` 里，或网站是 https 而聊天服务是 http。

**启动时报「缺少 LLM_BASE_URL / LLM_MODEL」？**
环境变量没设置好。在终端里要用 `export`，并且和启动命令在同一个窗口里执行。

**出现 `address already in use`？**
端口被占用，旧的服务还在运行。先停掉旧的（在原终端按 `Ctrl + C`），或者换一个端口（`export PORT=3002`）。

更多报错的处理办法见 `README.md` 的「常见报错和处理办法」。
